# 터미널 성능 측정

Embertop 터미널 화면은 초당 다섯 번 갱신됩니다.
`benchmark/terminal.mjs`는 오래 켜 두는 보조 프로세스로서의 비용을 좌우하는
세 경로를 측정합니다.

- 움직이는 92×36 대시보드 렌더링과 줄 단위 diff
- 바뀌지 않은 대시보드 렌더링과 줄 단위 diff
- 긴 요청 스트림을 제한된 1분 트래픽 창에 기록하는 작업

깨끗한 체크아웃에서 실행하십시오.

```bash
npm run benchmark:quick
npm run benchmark
npm run benchmark -- --json
```

각 시나리오는 한 번 예열한 뒤 독립된 반복 작업으로 측정합니다. 전체
프로필은 7회, 터미널 10,000프레임, 트래픽 레코드 100,000개를 사용합니다.
보고서에는 중앙값과 p95 실행 시간, 작업당 시간, 출력 체크섬, GC 뒤의 대략적
힙 변화량이 포함됩니다. 가비지 컬렉션과 런타임 내부 상태는 결정적이지 않기
때문에 힙 변화량은 음수일 수도 있습니다.

이 값은 회귀 비교를 위한 근거이지 모든 컴퓨터에서의 자원 사용 보장은
아닙니다. 같은 유휴 컴퓨터, Node.js 버전, 터미널 크기, 프로필끼리
비교하십시오. 스크립트는 터미널 출력·네트워크 연결·접근 로그 읽기를 하지
않고 고정된 합성 입력만 사용합니다.

## 참고 측정값

2026-08-13의 전체 실행은 Apple M1 Max가 탑재된 Darwin arm64에서 Node.js
v24.4.1을 사용했습니다. 중앙값 기준 핵심 비용은 움직이는 화면의 렌더링과
diff가 프레임당 77.924µs, 바뀌지 않은 화면이 73.413µs, 트래픽 창 기록이
건당 1.952µs였습니다. 제품의 초당 5프레임 주기라면 첫 번째 값은 1초당 약
0.39ms의 핵심 렌더링·diff 작업에 해당합니다.

이 측정은 실제 터미널 쓰기 지연, 텔레메트리 수집, 네트워크, 다른 프로세스
작업을 포함하지 않습니다. 다른 컴퓨터나 작업량을 보장하려는 값이 아니라
현재 기준선을 재현할 수 있게 하기 위한 값입니다.
